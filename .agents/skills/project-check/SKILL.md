# 프로젝트 검사

## 입력
실제 변경 파일·diff, `docs/testing.md`, `README.md`, 기존 `workspace/checks.md` 및 필요한 초기 구성 기록.

## 절차
모든 프로젝트 경로는 이 스킬이 속한 저장소 루트를 기준으로 한다. 루트의 `AGENTS.md`, `proposal.md`, `docs/project-brief.md`, `docs/workflow.md`, `docs/decisions/README.md`와 필요한 ADR을 읽는다. 아래 경로가 없으면 없는 상태를 보고하고 구현됐다고 추정하지 않는다.
확정 초기 정책은 영어 가상 기사·한국어 보고서·로컬 JSON·프로젝트 .venv + pip이며 API 미연결이다. 기존 확정 결정을 다시 묻거나 새 결정을 개인 대신 확정하지 않는다.

1. `docs/testing.md`를 검사 명령·대상·기대 결과의 기준으로 삼고 README와 실제 설정을 대조한다. 문서가 충돌하면 임의로 기준을 선택하거나 낮추지 않고 불일치를 기록한다.
2. 테스트 실행기·테스트 파일·환경 준비 여부를 확인한다. 명령이 미구성되었거나 테스트가 0개면 **준비 부족**으로 보고하고 통과로 판정하지 않는다. 명령을 임의로 만들거나 패키지를 설치하지 않는다.
3. 준비된 명령만 실제 실행한다. 현재는 외부 키·네트워크 없이 가능한 초기 검사만 대상이다. 실제 API 통합 검사는 개인의 연결·예산 결정과 testing.md의 실행 조건이 모두 갖춰진 경우에만 수행한다. 키 값을 읽어 출력하지 않는다.
4. 각 실행의 명령, 작업 폴더, 종료 코드, 핵심 출력, 실행 테스트 수와 기대 결과를 대조한다. 종료 코드 0만으로 테스트 0개·건너뛴 필수 검사까지 통과시키지 않는다. smoke test, mock/고정 표본, 실제 API 통합을 구분한다.
5. `workspace/checks.md`에 실행 번호·날짜·검사 종류·명령·종료 코드·출력 요약·판정·실패 원인·다음 조치를 추가한다. 실행하지 못한 명령은 종료 코드를 N/A로 적고 이유를 쓴다. 이전 기록은 보존한다. 필요 시 민감 정보를 제거한 원본 로그를 `workspace/logs/`에 두고 경로를 기록하되 Git에 올리지 않는다.
6. 전체 결과를 통과/실패/미실행으로 보고한다. 준비 부족은 별도로 명시한다. 초기 검사 통과로 기사 수집·분석·다국어·사실성 검증이 완료됐다고 쓰지 않는다.

## 산출물
`workspace/checks.md`, 필요한 원본 로그, 실행 증거와 미검증 범위 요약.

## 수정 범위와 중단 조건
검사 기록과 로그만 작성한다. 앱 코드·테스트·설정·테스트 계획을 고치거나 합격 기준을 변경하지 않는다. 실패 후 자동 수정하지 않고 작성자에게 구체적 원인을 넘긴다. 환경 미구성·권한 제한·문서 충돌·미승인 유료 연결이 필요하면 관련 검사를 멈추고 사유를 기록한다. 재검사·추가 수정 흐름은 workflow.md의 최대 2회 제한을 따른다.
