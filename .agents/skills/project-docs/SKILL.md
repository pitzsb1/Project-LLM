# 프로젝트 문서 갱신

## 입력
실제 변경 파일·diff, 개인의 실제 답변, `workspace/plan.md`, `workspace/checks.md`, `workspace/bootstrap-log.md` 중 존재하는 기록, README의 문서별 기준 정보 표.

## 절차
모든 프로젝트 경로는 이 스킬이 속한 저장소 루트를 기준으로 한다. 루트의 `AGENTS.md`, `proposal.md`, `docs/project-brief.md`, `docs/workflow.md`, `docs/decisions/README.md`와 필요한 ADR을 읽는다. 아래 경로가 없으면 없는 상태를 보고하고 구현됐다고 추정하지 않는다.
확정 초기 정책은 영어 가상 기사·한국어 보고서·로컬 JSON·프로젝트 .venv + pip이며 API 미연결이다. 기존 확정 결정을 다시 묻거나 새 결정을 개인 대신 확정하지 않는다.

1. 실제 변경과 기록을 읽고 기록이 없는 실행·없는 기능·개인이 하지 않은 결정을 분리한다. 증거가 없으면 미실행·미구성·미정으로 남긴다.
2. README의 기준 정보 표에 따라 갱신 대상을 고른다. 준비·검사 명령은 README, 범위·현재 상태는 project-brief, 검사 대상·명령·계획은 testing, 중요 결정은 decisions에서 관리한다. 내용 전체를 여러 문서에 복사하지 않는다.
3. 실행 명령을 README에 적을 때 실제 확인 기록과 연결한다. P4 전에는 testing.md를 참조하고 미구성 표시를 유지한다. API 미연결 상태나 초기 검사 결과를 실제 뉴스 분석 성공으로 바꾸지 않는다.
4. 새로운 중요 결정이 미확정이면 `docs/decisions/`에 **제안** ADR 초안(상태·배경·선택지·추천과 이유·영향·결정자 미정·날짜)을 남기고 개인 확인을 요청한다. 실제 개인 답변이 있는 결정만 확정으로 기록한다. 기존 결정 변경은 이전 기록을 보존하고 후속 ADR과 연결한다.
5. 필요한 문서만 갱신하고 링크·경로·현재 상태의 일관성을 확인한다. 원문 기사·키·개인정보·사용자 입력·실행 원본 로그를 문서로 복사하지 않는다.
6. `workspace/docs-update.md`에 실행 번호·날짜, 근거 변경/기록 경로, 갱신 파일·이유, 갱신하지 않은 항목과 이유, 남은 질문을 추가한다. 이전 기록을 보존한다. 스킬 파일 생성·직접 읽기 수행·실제 발견/호출 성공을 구분해서 적는다.

## 산출물
근거가 있는 관련 문서 갱신, 필요한 제안 ADR, `workspace/docs-update.md`.

## 수정 범위와 중단 조건
관련 문서와 문서화 기록만 수정한다. 앱 코드·테스트·환경·제안서 원문은 수정하지 않는다. 새로운 중요 결정은 초안 이후 답변을 기다리고 의존 내용을 확정하지 않는다. 실제 변경과 기록이 충돌하면 확인 가능한 부분만 반영하고 충돌과 필요한 확인을 남긴다. 작업이 끝나면 개인이 채택했다고 대신 기록하지 않는다.
