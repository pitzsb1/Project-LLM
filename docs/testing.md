# 테스트 계획

갱신일: 2026-10-28. P4 구성 완료. 프로젝트 .venv의 Python 3.11.11에서 정식 초기 검사 4개 통과.

## 현재 구성과 정식 검사 명령
프로젝트 루트에서 Python 3.11로 `.venv`를 준비한 뒤 실행한다.

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
PYTHONPATH=src .venv/bin/python -m news_crosscheck
```
첫 명령은 `Ran 4 tests`와 `OK`, 종료 코드 0이 기대 결과다. 테스트 0개·건너뜀·버전 불일치는 통과가 아니다. 둘째 명령은 `Harness config loaded: news-crosscheck`, `API enabled: False`, `News analysis: not implemented`와 종료 코드 0이 기대 결과다. 이것은 설정 확인 진입점이며 앱 실행이 아니다.

검사 대상: Python 3.11 일치, `src/news_crosscheck/config.py`의 실제 TOML 로딩, 영어 입력·한국어 출력/오프라인·JSON 정책, 설정이 가리키는 가상 JSON 파일의 존재·구조·가상 표시·예약 URL. 외부 키·네트워크·써드파티 패키지 없이 실행한다.
`requirements.txt`는 현재 표준 라이브러리만 사용함을 기록한다. .env.example은 현재 환경 변수 사용이 없어 불필요하다.

## 실제 실행 상태
초기 Python 3.14.4 진단은 버전 검사 1개 실패했으나, py311 커널 경로를 확인한 뒤 프로젝트 .venv를 Python 3.11.11로 생성했다. 정식 검사 4개 통과(종료 코드 0), 설정 확인 명령 종료 코드 0. 이전 실패 기록도 보존했다. 초기 증거는 [bootstrap-log](../workspace/bootstrap-log.md), P5 재실행 증거는 [checks](../workspace/checks.md)다. Python 버전 기준을 낮추지 않는다.

## 제안서에서 도출한 시나리오 — 모두 계획
- 정상: 5개 국가·지역 가상 기사와 3개 이상 독립 출처 조건을 갖춘 동일 사건에서 공통 정보·관점·출처가 구분된다(§3.1).
- 경계: 기사는 여러 개지만 같은 통신사 재인용이거나 출처가 부족하면 독립 근거 수를 부풀리지 않고 부족함을 표시한다(§2.2, §3.1).
- 실패: 본문 수집 실패·API 오류·사상자 수 불일치 시 결과를 지어내지 않고 실패/불일치·추가 확인 항목으로 남긴다(§3.1~3.2).
최소 5개 국가·지역 수집 목표와 3개 출처 비교 목표는 별도로 평가한다. 가상 표본 검사는 실제 기사 수집 달성을 입증하지 않는다.

## LLM·검색·외부 API 평가 계획
고정 표본과 사람이 확인한 근거를 사용해 주장 분류, 근거 문장과 인용 URL의 일치, 근거 없는 주장, 모순·불확실성 보존을 평가한다. 반복 실행 시 모델 ID·프롬프트·표본 버전을 남긴다. 구체적 정답 표본·합격 임계값·평가 횟수는 후속 개인 결정으로 남긴다.
검색은 동일 사건·시점 관련성, 국가/지역 범위, 독립 출처 다양성, 중복 및 수집 실패를 확인한다. 번역·현지어 정확성은 현재 미검증이며 이후 범위를 정한다. ROUGE/문자열 유사도만으로 사실성을 판정하지 않는다.

## 검사 종류와 증거
- 오프라인 smoke test: tests/test_smoke.py에 구성. 환경·모듈/설정·표본 로딩만 확인하며 정식 3.11 실행 4개 통과.
- 오프라인 mock/고정 표본 검사: 향후 기능 검증. 실제 검색·모델 성능을 입증하지 않는다.
- 실제 API 통합 검사: 개인의 연결·예산 결정 후 실시. 현재 미실행이고 초기 통과 기준에 포함하지 않는다.
검사자는 `workspace/checks.md`에 실행 번호·시각·명령·종료 코드·출력 요약·필요 시 원본 로그 경로와 통과/실패/미실행을 남긴다. 초기 구성 증거는 `workspace/bootstrap-log.md`에 남긴다. 원본 로그는 Git에서 제외하고 제출용 요약은 민감 정보 없이 별도 구분한다.
실패 시 재시도 제한과 책임은 [workflow](workflow.md)를 따른다. 초기 검사 통과는 앱 기능 완성이나 뉴스 정확성 검증 완료가 아니다.
